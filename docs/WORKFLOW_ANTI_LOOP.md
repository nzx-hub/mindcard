# 防循环工作流

这份文档记录本项目一次典型的“重复思考 / 重复试错”事故，以及之后必须遵守的止损规则。

## 事故表现

1. Tauri 构建连续遇到不同错误后，反复执行同一类构建/轮询命令。
2. 为排查 WebView2 启动失败，先后尝试日志、环境变量、自定义数据目录、Explorer 启动、浏览器参数、NSIS 下载，但没有先定义“到什么程度停止”。
3. 最终回复出现大段重复段落，属于输出退化，不是有新信息。
4. 上下文被大量完整构建日志、错误堆栈和重复描述占满，后续判断质量下降。

## 根因

### 1. 没有完成标准

“做出 Tauri 效果”没有拆成可验收的产物：
- 编译通过？
- 窗口能开？
- 能安装？
- 数据能持久化？

目标每失败一次就临时换一个，导致无限扩展。

### 2. 失败预算缺失

同一个构建错误重复出现时，仍然继续“再试一次”，而不是换工具链、换打包方式或停下来报告。

### 3. 工具调用不改变状态

反复读取同一个后台任务、重复同一条构建命令，不会产生新信息；应该等待完成通知，或改用不同诊断维度。

### 4. 环境问题和代码问题混在一起

中文路径、MinGW、WebView2、沙箱、NSIS 网络下载，都是环境问题；代码本身可能已经正确。没有先隔离环境，导致每次错误都像是“程序又坏了”。

### 5. 输出没有长度和结构约束

长上下文 + 长错误日志 + 连续“继续”指令，容易让模型进入续写循环；最终答案没有做重复段落自检。

## 强制规则

### 规则 1：先写状态板

每次任务开始时只写四行：

```text
目标：
完成标准：
已知事实：
下一步：
```

状态板变化时才更新，不重复复述历史。

### 规则 2：两次失败必须换维度

同一个操作连续失败两次，禁止原样重试。只能：
- 换工具链（GNU → MSVC）；
- 换交付方式（安装包 → 便携包）；
- 换验证方式（启动 → 静态检查）；
- 或停下来向用户说明阻塞点。

### 规则 3：构建日志只留摘要

完整日志写入文件，对话里只保留：
- 第一条错误；
- 最后一次错误；
- 已排除的假设。

### 规则 4：探索和交付分开

探索阶段最多尝试一种主路径和一种备选路径；超过就交付当前最小可用产物，并明确未完成项。

### 规则 5：最终回复限长、查重

- 一个结论只出现一次；
- 不再重复大段已发内容；
- 发送前检查是否有重复标题/重复段落；
- 默认不超过约 80 行，除非用户要求详细文档。

### 规则 6：环境限制不算产品失败

如果窗口在受限沙箱里被 WebView2/权限拦截，但 exe 已构建成功：
- 记录为“当前环境无法验证”；
- 给出普通桌面验证步骤；
- 不继续在同一环境里反复重启。

- 不再重复尝试 NSIS 下载；
- 不再在当前受限桌面会话里反复启动 WebView2；
