审计对象：`app/index.html`、`app/app.js`、`app/deck-store.js`、`app/styles.css`、`decks.js`、GitHub Actions。  
目标：找出还会影响“数据安全、可用性、可维护性”的问题，暂不修改代码。

**结论**：功能已经完整，但仍有 **4 个可能丢数据的 P0 问题**、若干体验与架构问题。最该先修的是：静默保存失败、进度导入误判、全部卡组挤在一个存储键、损坏状态静默重置。

## P0：数据安全

### 1. 保存失败是静默的

`app/app.js:56`：

```js
try { localStorage.setItem(STORE, JSON.stringify(S)); }
catch (e) { /* 隐私模式等情况下静默失败 */ }
```

- 隐私模式、存储配额满、Safari 清理策略触发时，评分看起来成功了，刷新后却回到旧状态；
- 用户没有任何提示，也不知道该导出备份。

**建议**：改为返回成功/失败；失败时弹持久提示“本次修改未保存，请立即导出 JSON”，并在顶栏显示“存储不可用”。

### 2. “导入学习进度”会把卡组 JSON 当成进度

`app/app.js:1221`：

```js
var obj = JSON.parse(text);
if (!obj || !obj.cards) throw new Error(...);
S.cards = obj.cards || {};
```

卡组 JSON 也有 `cards` 字段（数组），于是：

- `S.cards` 被替换成数组，当前卡组进度实际被清空；
- `S.log`、`S.hidden` 被空值覆盖；
- 用户以为只是“导入失败”，其实进度已经没了。

**建议**：进度文件必须校验 `v===1`、`deckId` 存在、`cards` 是对象而不是数组；检测到卡组 JSON 时明确提示“这是卡组，请到卡组页导入”。

### 3. 所有导入卡组塞在一个 localStorage 键里

`deck-store.js:28` 把全部导入卡组写进 `mindcard:decks` 一个键：

- 任何一次保存都要序列化所有卡组；
- 一个 JSON 损坏，所有导入卡组一起丢；
- 5 MB 上限很快到；卡组越多，添加一张卡越慢。

**建议**：改用 IndexedDB（一个卡组一条记录），或至少一个卡组一个 `localStorage` 键，并做配额检测。

### 4. 存储损坏时静默重置

`app/app.js:45` `loadState()` 解析失败直接 `return null`，随后 `defaultState()`：

- localStorage 被截断/写坏/版本不符时，界面像“新安装”；
- 没有恢复入口，也没有备份。

**建议**：解析失败时保留原始字符串到 `mindcard:corrupt:<time>`，提示用户并可下载；启动时优先恢复最近备份。

### 5. 没有自动备份，也没有“导出全部”

- 设置里只能导出**当前卡组**的进度；
- 卡组内容要逐个导出；
- 删除卡组会同时删进度，只弹一次确认，不提示先导出。

**建议**：增加“导出全部（卡组 + 进度 + 设置）”的单文件备份，写入前自动留一份 `.bak`。

### 6. 多标签页会互相覆盖

代码里没有监听 `storage` 事件，也没有锁：

- 两个标签页同时评分，后保存的覆盖先保存的；
- 一个标签页删除卡组，另一个仍持有旧数据。

**建议**：监听 `storage` 事件提示重载；评分采用“版本号 + 合并”或至少单写锁。

### 7. 移动端存储可能被清理

Safari 对非安装站点可能清理脚本可写存储；隐私模式关闭后数据消失。应用没有 PWA/持久化申请。

**建议**：`navigator.storage.persist()` + 引导“添加到主屏幕” + 定期导出。

### 8. 删除不可恢复

删除卡片/卡组只有 `confirm`，没有回收站（卡片有，卡组没有），也不自动导出。误删即永久丢失。

**建议**：卡组改为软删除/回收站，或删除前强制导出。

## P1：功能与体验

### 9. 主题是按卡组存的，不是全局的

`settings.theme` 存在每个卡组的进度里（`app.js:33`）。切到另一个卡组时主题可能变回浅色；新卡组也不继承你刚设的深色。

**建议**：主题、语言、字号放到全局 `mindcard:settings`。

### 10. 大卡组编辑器没有搜索/分页

编辑 156 张（或克隆的 300 张）卡时，卡片列表全部渲染，找一张要滚很久。没有搜索、按题型筛选、批量操作。

**建议**：加搜索框和题型筛选；列表分页或虚拟滚动；支持批量删除。

### 11. Markdown 多行答案会丢

`deck-store.js:237` 只取 `A:` 那一行：

```js
if (ma && pendingQ) { addCard(pendingQ, ma[1], '问答'); ... }
```

答案换行、分点、代码块时，后续行不会被并入答案，直接丢失。代码围栏里的 `#`/`|` 还会被误判为标题/表格。

**建议**：解析器支持多行答案、围栏代码块；和 CLI 共用一套规则与测试。

### 12. 导入没有大小限制和编码处理

- 任意大 JSON 直接 `JSON.parse`，主线程会卡死；
- `FileReader.readAsText(file, 'utf-8')` 读 GBK 中文文本会乱码；
- 没有文件大小、卡片数量上限。

**建议**：限制 10–20 MB；大文件分片/Worker；检测 UTF-8 BOM/GBK 或提示另存为 UTF-8。

### 13. 评分不能撤销，也不能跳过

点错“简单”会直接跳两级，只能继续；不想答的卡也只能先评分。

**建议**：加“撤销上一张”和“跳过（稍后）”。

### 14. `?deck=` 链接会让切换失效

`deck-store.js:51` 优先读 URL 的 `deck` 参数，`setActive()` 只写 localStorage：

- 打开 `index.html?deck=A` 后切到 B，刷新仍回到 A；
- 分享链接切换卡组会“卡住”。

**建议**：切换时同步更新 URL，或让 localStorage 优先。

### 15. 非当前卡组删卡会留下旧进度

`deleteDeckCard()` 只在 `deck.id === DECK.id` 时清理 `S.cards`。删除非活动卡组的卡片，其进度仍留在那个卡组的存储里；之后若导入同 id 卡组，旧状态可能被错误复用。

**建议**：读取目标卡组的进度并删除对应条目，或明确接受残留。

### 16. 没有错误边界，异常会留下旧页面

`render()` 没有 try/catch。之前一次函数被误删，表现就是“点卡组页没反应，还停在今日”，控制台才有错。

**建议**：`render()` 包一层错误面板，显示“页面出错 + 刷新/导出数据”，并把错误写到可复制的诊断信息里。

### 17. 畸形链接会让编辑器崩溃

`app.js:775` 直接 `decodeURIComponent`，`#/edit?id=%` 这类链接会抛 `URIError`，页面停在旧内容。

**建议**：try/catch，失败时提示“链接无效”。

### 18. 编辑器没有“未保存”提示

表单填了一半，点导航或刷新就没了（已保存的卡片不受影响）。

**建议**：监听 `beforeunload`，或保存草稿到 sessionStorage。

### 19. “计划卡片数”只是展示

`targetCards` 不限制添加，超过目标仍显示 `5 / 3`。如果用户以为是硬限制，会困惑。

**建议**：文案写清“计划数，不限制”，或超过时给柔和提示。

### 20. 同 id 重新导入会保留旧进度

`saveImported()` 覆盖卡组但保留 `mindcard:progress:<id>`。如果新版本卡组复用了卡片 id 却换了题目，进度会错误对应。

**建议**：导入时比较卡片 id/内容哈希，提示“保留进度/重置进度”。

## P2：架构与维护性

### 21. `app.js` 已接近 80 KB，单文件 + 全局状态

SRS、视图、编辑器、导入导出、存储全在一个 IIFE 里；没有模块边界，单元测试很难写。

**建议**：按 `core/srs`、`core/deck`、`storage`、`views` 拆分；先抽纯函数，UI 后拆。

### 22. 浏览器和 CLI 是两套解析器

`app/deck-store.js` 和 `tools/convert.py` 各自实现 Markdown 规则，已经开始漂移（多行答案、表格、标题层级）。

**建议**：写一份共享的解析规范 + 黄金用例；两边跑同一组 fixtures。

### 23. 没有自动化测试，CI 也不检查前端 JS

- 仓库没有 `tests/`；
- `validate.yml` 只校验卡组和 `app/decks.js` 是否最新；
- 之前“误删 viewDecks”这类回归，只能靠人工发现。

**建议**：加 `node --check`、Playwright 冒烟（建组→加卡→复习→刷新）、解析器黄金测试。

### 24. 进度没有 schema 版本与校验

卡组有 `schemaVersion`，进度只有 `v:1`，且导入时不校验字段类型；一个 `due: "abc"` 就能让排程算 NaN。

**建议**：进度也加 `schemaVersion` 和校验/迁移函数。

### 25. 没有 PWA

没有 `manifest.webmanifest` 和 service worker：

- 不能“安装”；
- 断网后 GitHub Pages 首次加载失败；
- 手机端更容易被清存储。

**建议**：加 manifest + 预缓存 app shell + 版本提示。

### 26. 资源没有版本号，部署后可能看到旧代码

`index.html` 直接引用 `app.js`、`styles.css`；GitHub Pages 缓存约 10 分钟，部署后用户可能新旧混用。

**建议**：构建时加 hash/`?v=`，或 service worker 控制更新。

### 27. 死代码

- `hasSheet()` 恒为 `false`（`app.js:344`），但 `#/sheet` 路由与 `viewSheet()` 还在；
- 导航里已经没有“速查”，相关文案仍残留。

**建议**：删除或恢复为“卡组 extras”功能，别留半成品。

### 28. 没有 i18n

UI 全是中文，卡组的 `language` 字段没有参与界面；英文卡组也只能看中文按钮。

**建议**：先把 UI 文案抽到 `i18n/zh-CN.js`，再决定是否做英文。

### 29. 没有错误日志/诊断

用户遇到问题时，只能截图；没有“复制诊断信息”（浏览器、存储用量、卡组数量、最近错误）。

**建议**：设置页加诊断面板和“复制”。

## P3：兼容、无障碍与细节

### 30. `color-mix` 与 `backdrop-filter` 没有降级

`styles.css` 有 7 处 `color-mix`；旧浏览器会丢弃这些声明，部分边框/背景消失。顶栏还依赖 `backdrop-filter`。

**建议**：给关键颜色写 `background-color` 兜底，`@supports` 渐进增强。

### 31. 表单 label 没有关联控件

全项目 `<label for=...>` 数量为 0；编辑器标签点击不会聚焦输入框，读屏软件也难以关联。

**建议**：补 `for`/`id`，或把输入包进 `<label>`。

### 32. 路由切换不移动焦点，toast 没有 aria-live

- 单页应用换页后，键盘/读屏用户还停在旧位置；
- `#toast` 没有 `role="status"`。

**建议**：换页后 `focus()` 到 `h1`；toast 加 `aria-live="polite"`。

### 33. 小号 muted 文字对比度偏低

`--muted` 在浅色底上约 3.3:1，而它常用于 11–12 px 文本，低于 WCAG AA 的 4.5:1。

**建议**：加深 muted，或只在大字号使用。

### 34. 移动端没有安全区处理

`viewport-fit=cover` 但 CSS 没有 `env(safe-area-inset-*)`，刘海屏上顶栏可能被遮挡。

### 35. 没有打印样式

打印卡组/统计会带导航和阴影；没有 `@media print`。

### 36. 24 处 `alert`、10 处 `confirm`

原生弹窗风格与应用不一致，移动端体验差；确认文案有的很长。

**建议**：逐步换成自定义 modal/toast，至少把“删除/覆盖”统一。

### 37. 卡组列表没有排序/搜索

卡组多了以后只能按插入顺序找；没有“最近使用”“按名称”。

### 38. 没有分享/OG 信息

分享链接在聊天软件里没有标题、描述、缩略图。

### 39. 没有 CSP

内容都做了转义，但没有 CSP 兜底；一旦未来某处漏转义，浏览器没有第二道防线。

### 40. 数据是明文

同一台电脑的其他使用者打开浏览器开发者工具就能看到卡组和进度；没有锁屏/PIN。

- 用户内容基本都经过 `esc`/Markdown 子集渲染，没有明显 XSS；
